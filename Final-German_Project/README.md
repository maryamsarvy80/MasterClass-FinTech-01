# پیش‌بینی نکول در اعتبارسنجی مشتریان

این پروژه یک تحلیل آموزشی و اولیه روی دیتاست **German Credit (Statlog)** است. هدف آن بررسی یک خط لوله‌ی امتیازدهی اعتباری برای رتبه‌بندی پرونده‌ها بر اساس احتمال نکول و مقایسه‌ی چند مدل پایه است؛ خروجی پروژه جایگزین بررسی اعتباری یا تصمیم کارشناسی نیست.

## محتویات پروژه

- `project_german_credit.ipynb` — نوت‌بوک تحلیل، آماده‌سازی داده، آموزش و مقایسه‌ی مدل‌ها، انتخاب آستانه، ارزیابی و توضیح‌پذیری.
- `german.data` — فایل خام داده که باید پیش از اجرای نوت‌بوک در همین پوشه قرار گیرد.
- `requirements.txt` — وابستگی‌های لازم برای اجرای نوت‌بوک.
- `figures/` — پوشه‌ای که نوت‌بوک نمودارها را در آن ذخیره می‌کند؛ در صورت نبود، هنگام اجرا ساخته می‌شود.

## داده‌ی ورودی

نوت‌بوک فایل `german.data` را با جداکننده‌ی فاصله/فاصله‌های متوالی می‌خواند و انتظار دارد فایل در دایرکتوری کاری نوت‌بوک باشد. این فایل از مجموعه‌ی **Statlog (German Credit Data)** مخزن UCI Machine Learning Repository است:

- صفحه‌ی مجموعه‌داده: https://archive.ics.uci.edu/dataset/144/statlog+german+credit+data
- فایل خام: https://archive.ics.uci.edu/ml/machine-learning-databases/statlog/german/german.data
- توضیحات متغیرها: https://archive.ics.uci.edu/ml/machine-learning-databases/statlog/german/german.doc

پس از دریافت، نام فایل را دقیقاً `german.data` بگذارید. این نسخه دارای ۱۰۰۰ پرونده و ۲۰ ویژگی ورودی است. نوت‌بوک کدهای خام دسته‌ای را به برچسب‌های متنی نگاشت می‌کند و `default=1` را نکول و `default=0` را خوش‌حسابی در نظر می‌گیرد.

## نصب و اجرا

Python نسخه‌ی ۳٫۱۰ تا ۳٫۱۲ پیشنهاد می‌شود.

```bash
python -m venv .venv
```

فعال‌سازی محیط مجازی:

```bash
# Windows PowerShell
.venv\Scripts\Activate.ps1

# macOS / Linux
source .venv/bin/activate
```

نصب کتابخانه‌ها و راه‌اندازی Jupyter:

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
jupyter notebook
```

سپس `project_german_credit.ipynb` را باز کنید، مطمئن شوید `german.data` در همان پوشه است و سلول‌ها را به ترتیب از ابتدا اجرا کنید. اجرای کامل بخش مدل‌ها ممکن است به دلیل جست‌وجوی ابرپارامترها و محاسبه‌ی SHAP چند دقیقه طول بکشد.

## نمای کلی روش

1. بارگذاری و اعتبارسنجی داده و بررسی مقادیر و توزیع‌ها.
2. تعریف برچسب دودویی نکول و بررسی نسبت کلاس‌ها.
3. جداسازی طبقه‌بندی‌شده‌ی آموزش و آزمون؛ آزمون برای ارزیابی نهایی نگه داشته می‌شود.
4. مهندسی ویژگی و پیش‌پردازش درون `Pipeline` تا برازش تبدیل‌ها داخل Fold آموزشی انجام شود.
5. مقایسه‌ی درخت تصمیم، XGBoost و رگرسیون لجستیک با اعتبارسنجی متقاطع طبقه‌بندی‌شده.
6. انتخاب Cut-off با استفاده از پیش‌بینی‌های Out-of-Fold روی داده‌ی آموزش و ماتریس هزینه‌ی فرضی پروژه.
7. ارزیابی یک‌باره روی آزمون و بررسی ROC-AUC، PR-AUC، Brier، ماتریس خطا و نمودار کالیبراسیون.
8. بررسی توضیح‌پذیری مدل با SHAP و LIME.

## خروجی‌ها

نوت‌بوک شکل‌ها را در `figures/` ذخیره می‌کند؛ از جمله نمودارهای EDA، منحنی هزینه، ماتریس‌های خطا، نمودارهای ROC/Precision–Recall/Calibration، درخت پایه، نمودارهای SHAP و LIME. جدول‌ها و معیارهای عددی نیز هنگام اجرای سلول‌های مربوط در نوت‌بوک نمایش داده می‌شوند.

## ملاحظات مهم

- داده تاریخی است و فقط پرونده‌هایی را شامل می‌شود که وام آن‌ها پذیرفته شده است؛ بنابراین **سوگیری انتخاب** و محدودیت تعمیم به کل متقاضیان محتمل است.
- داده ستون زمان درخواست ندارد؛ این پروژه اعتبارسنجی Out-of-Time انجام نمی‌دهد و تقسیم تصادفی جایگزین آزمون زمانی نیست.
- هزینه‌ی FN و FP در پروژه نسبت فرضی ۵ به ۱ دارد. هزینه‌های گزارش‌شده واحدهای نسبی این ماتریس‌اند و مبالغ پولی یا برآورد صرفه‌جویی واقعی نیستند.
- متغیر ساخته‌شده‌ی `debt_burden` در کد برابر `duration × installment_rate / 100` است؛ این متغیر DTI یا نسبت واقعی اقساط به درآمد نیست. `monthly_payment` نیز مبلغ اعتبار تقسیم بر مدت است و بهره/کارمزد را لحاظ نمی‌کند.
- توضیح‌های SHAP و LIME شرح رفتار مدل‌اند و باید با تعریف دقیق ویژگی‌ها و زمینه‌ی داده تفسیر شوند. وجود ویژگی حساس در میان عوامل برجسته، ضرورت ممیزی Fairness را نشان می‌دهد.
- هیچ خروجی این پروژه نباید به‌تنهایی برای رد یا تأیید خودکار درخواست واقعی استفاده شود. پیش از کاربرد عملیاتی، اعتبارسنجی زمانی و مستقل، بررسی کالیبراسیون و عدالت، پایش drift، کنترل انسانی و فرایند حکمرانی مدل ضروری است.
